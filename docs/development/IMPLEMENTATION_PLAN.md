# V-Lab ECE: Implementation Plan (Agent-Executable)

> **Audience:** autonomous coding agent (Google Antigravity). Execute tasks **strictly in ID order** unless a task's `Depends` column allows parallel work. Read the referenced docs before starting a task.

## 1. Agent Operating Protocol

1. **One task = one branch = one PR.** Branch `task/T-019-run-pipeline`. Commit message format: `feat(engine): T-019 run pipeline` (Conventional Commits; scope from `CODING_STANDARDS.md` §9).
2. **Before coding:** read the task row, the docs it cites, and the ACs it lists in `ACCEPTANCE_CRITERIA.md`.
3. **Definition of Done for every task:**
   - `pnpm verify` passes (runs `typecheck`, `lint`, `test`, `ac-coverage`, `engine-pin-check`).
   - Every AC listed on the task has at least one test named `AC-<ID>: ...`.
   - Docs touched by the change are updated in the same PR.
   - No `any`, `@ts-ignore`, `eslint-disable` without an issue-linked comment.
4. **Never skip ahead.** A task whose dependency is not merged is blocked.
5. **Blocker protocol:** if a doc is ambiguous, contradicts another doc, or an AC cannot be met, create `docs/BLOCKERS.md` entry `B-<n>: <task> | <problem> | <options>` and stop that task. Do not weaken ACs, limits, or security headers to pass.
6. **Version protocol:** follow `TECH_STACK.md` header. Record resolved versions in `docs/architecture/RESOLVED_VERSIONS.md`.
7. **No network calls to third-party origins at runtime.** Anything the browser needs is self-hosted (ADR-012).
8. **Determinism:** tests use fixed seeds; no wall-clock assertions except those defined as performance ACs.
9. **Task output report:** after each task append a line to `docs/PROGRESS.md`: `T-019 | done | <PR> | ACs: AC-ENG-005, AC-ENG-009 | notes`.

## 3. Detailed Specs for Critical Tasks

### 3.1 T-019: Run pipeline (worker)

Implement in `pyodide.worker.ts` plus `vlab/_runtime.py`.

1. **Namespace:** create once at boot: `ns = pyodide.globals.get("dict")()`; set `ns["__name__"] = "__main__"`. Persist across runs until the worker is terminated (AC-ENG-005).
2. **Pre-run:** on `RUN_CODE`, reject if a run is active (`E_INTERNAL`); validate limits against the hard maxima in `limits.ts`; reset stdout byte counter; write `params` into the Python-visible dict `vlab._runtime.PARAMS`.
3. **Checks:** call `vlab.policy.check(code)`; on failure post `RUN_FAILED` with `E_SYNTAX` or `E_POLICY_VIOLATION`, including `line` and `column`.
4. **Packages:** `pyodide.loadPackagesFromImports(code)` restricted by the allowlist (SCOPE §4.3); any non-allowlisted import fails with `E_POLICY_VIOLATION` **before** loading.
5. **Streaming:** `pyodide.setStdout({ batched })` and `setStderr`; accumulate into a buffer flushed by a 16 ms timer as `STREAM_OUTPUT`. If cumulative bytes exceed `maxStdoutBytes`, stop forwarding, send one system line "Output truncated (2 MB limit)", and raise `E_LIMIT_STDOUT` as a warning inside `RUN_COMPLETED` (do not abort the run).
6. **Execute:** `vlab._runtime.run(code, ns, selection)` compiles with filename `"<user>"` and `exec`s it. It catches `BaseException` (except `SystemExit`, which becomes a normal completion), then returns `{ok, name, message, line, column, traceback}` where `traceback` contains only frames whose filename is `<user>`; line numbers map 1:1 because the filename is fixed. For `selection: true` the UI sends only the selected text and a line offset `lineOffset` field is added to the Python call so reported lines are shifted back (add `lineOffset?: number` to `RUN_CODE`; update protocol and SYSTEM_ARCHITECTURE §6 in the same PR).
7. **Figures:** `vlab.*` builders call a JS callback registered at bootstrap (`pyodide.registerJsModule("_vlab_bridge", { emitFigure })`; the module is removed from `sys.modules` for user visibility but the bridge function reference is retained inside `vlab`). `emitFigure` converts arrays with `to_js`, builds the transfer list from typed-array `.buffer`s, and posts `FIGURE_READY`.
8. **After run:** build `VariableInfo[]` (skip names starting with `_`, modules, functions, `vlab`); for ndarrays compute `shape`, `dtype`, `nbytes`, preview (first 6 elements). If any ndarray has `size > maxArrayElements`, post `RUN_FAILED(E_LIMIT_ARRAY)` and delete that variable from the namespace. Then post `VARIABLES_UPDATED` and `RUN_COMPLETED` with `elapsedMs` from `performance.now()`.
9. **Tests:** AC-ENG-005 (state persistence), AC-WS-005 (line mapping), AC-ENG-009 (array and stdout limits), AC-WS-004 (batch cadence with fake timers).

### 3.2 T-020: Cancellation, timeout, memory

- **Interrupt:** at INIT, if `interruptBuffer` is non-null call `pyodide.setInterruptBuffer(new Int32Array(buffer))`. Before each run set `Atomics.store(arr, 0, 0)`.
- **Stop (main thread):** `WorkerManager.stop(runId)`: if isolated, `Atomics.store(arr, 0, 2)`; start a `CANCEL_GRACE_MS` timer; on `RUN_CANCELLED` clear it; on expiry call `terminate()`, emit `CANCEL_GRACE_EXPIRED`. If not isolated, terminate immediately (state `Restarting` path with message "Kernel reset").
- **Single long native call:** a single NumPy call (for example one huge FFT) cannot be interrupted. Stop therefore always ends in terminate after the grace period; document in the UI text ("Stopping long numerical calls resets the kernel").
- **Timeout:** timer owned by the **main thread** (the worker is blocked while computing): at `limits.timeoutMs` call `terminate()` and emit `RUN_TIMEOUT`.
- **Memory:** (a) after each run the worker reports `MEMORY_STATS` with `pyodide._module.HEAPU8.byteLength / 2**20`; (b) if above `maxWorkerHeapMb` after a run, show a warning and recommend Restart; (c) while running and `crossOriginIsolated`, the main thread polls `performance.measureUserAgentSpecificMemory()` every 1,000 ms; if the page total exceeds `maxWorkerHeapMb + 300` MB, terminate with `E_LIMIT_MEMORY` (constant tunable in T-083); (d) a worker `error`/`messageerror` event or `RangeError: memory access out of bounds` maps to `E_LIMIT_MEMORY`.
- **Respawn:** after any terminate the manager creates a new Worker, sends INIT, and the machine transitions `Terminated -> Booting` automatically.
